# v1.6.0-rc.3 — верные тёмные цвета и Mini VU без пробивающихся часов

**Предрелиз. Последняя стабильная версия — v1.5.5.**

## Цвета обложки: обе стоковые Капсулы

Серый фон и тени теперь учитываются в долях палитры. Тёмные оттенки
больше не высветляются принудительно до 55%. На Hybrid Theory прежний
алгоритм отдавал почти всё кольцо яркому красному; новый выбирает
10 приглушённых серых и 2 тёмно-бордовых stop.
Малые светлые акценты по-прежнему не получают половину кольца.
Калибровка, яркость панели и пульсация кольца сохраняются.

Владелец принял результат на Mini; тот же цветовой фикс установлен
UI-only на большую, без перезапуска приёмника и LED-брокера.

## Mini: автояркость больше не возвращает часы поверх VU

При фонарике штатный процесс обновлял яркость и перерисовывал часы поверх
прямых sysfs-записей VU. Теперь UI вообще не пишет в сегменты напрямую:
кадры передаются по локальному сокету единому арбитру в штатном процессе.
Арбитр сохраняет нативную яркость, распознаёт рисунок часов независимо от
её уровня и возвращает штатный кадр в паузе/при исчезновении UI.

Это не FFT: четыре семисегментные цифры показывают плавную волну реального
уровня музыки. Штатные не-часовые кадры имеют приоритет.
Ранний неудачный запуск адаптера защищён startup guard и stock fallback.
Аудиовызовы и учётные данные не перехватываются.

Владелец повторил тест после контролируемой перезагрузки и подтвердил
«работает». В двухминутном замере: яркость 1→13→1 и 1→11→1,
45 предотвращённых перерисовок часов, 0 ошибок драйвера; переход в паузу
освободил экран. Полный тур громкости/речи, длительная стабильность и
новая установка на чистой колонке отдельно не квалифицированы.

## Установка на стоковую Mini

В каталоге `packages/mini-stock`:

```sh
sh install.sh --upgrade --display-vu
```

**После первой установки арбитра нужна одна ручная перезагрузка Mini.**
Не останавливайте и не перезапускайте `voice-agent`: с ним связан watchdog.
Установщик сам не перезагружает колонку; до загрузки арбитра остаются
штатные часы. Владелец на своей Mini этот шаг уже выполнил.

Поддерживается только проверенная stock Mini Buildroot с известным
voice-agent; неизвестная прошивка/обёртка отвергаются до обновления.
Арбитр загружается только в её процесс, не через глобальный LD_PRELOAD.
Маппированная библиотека заменяется атомарно, а не перезаписывается.
`--check` проверяет совместимость без установки. Обычное обновление
сохраняет выбор VU; новая установка по умолчанию оставляет часы.

Для немедленного возврата часов без прерывания музыки:

```sh
rm -f /data/local/capsula-airplay/etc/mini-display-vu.enabled /tmp/capsula-mini-display-vu
```

При обновлении можно передать `--clock`. Полный установщик останавливает
AirPlay для обновления и делает backup; это не UI-only live-замена.
Полное удаление адаптера из уже работающего процесса происходит только
после перезагрузки; без VU-lease он прозрачно пропускает штатные кадры.

## Остальные компоненты / ограничения

- Приёмники Mini/Big не менялись относительно rc.2: −1.7 / 0.15 сохранены.
- Эксперимент стартовой синхронизации большой из rc.1 остаётся в комплекте:
  повторные подключения ещё могут давать drop-late/underrun. Это НЕ
  завершённый фикс стартовых фризов, поэтому выпуск остаётся RC.
- Alpine payload не менялся. Windows ZIP-мастер предназначен только
  для Alpine-Мини, не для стоковой.
- Пакет не прошивает устройство, не переносит userdata и не меняет аккаунт.

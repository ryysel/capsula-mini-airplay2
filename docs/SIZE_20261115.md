# Как уменьшен размер поставки — 15.11.2026

Ориентир — сборка Station AirPlay для Яндекс Станций: там весь приёмник
(AirPlay 2, nqptp, супервизор, индикация) укладывается в один архив
~4,9 МБ. Ниже — что именно они делают, что из этого применено у нас и что
получилось по факту.

## Что делает Station AirPlay

Их скрипты сборки (`scripts/build-airplay2.sh`, `.github/workflows/ci.yml`):

- **C/C++**: `-Os`, `-flto`, `-ffunction-sections -fdata-sections`,
  `-Wl,--gc-sections`, `-mthumb`, `-ffile-prefix-map` для воспроизводимости;
  ffmpeg собирается с `--enable-small --disable-everything` и только нужными
  декодерами (aac, alac, pcm_s16be), демоны — без systemd, D-Bus, MPRIS, soxr;
  всё лишнее вырезается `strip`.
- **Go-супервизор**: `CGO_ENABLED=0`, `-buildvcs=false -trimpath`,
  `-ldflags='-s -w'`, затем `upx --best --lzma` и проверка `upx -t`.
- **Упаковка**: один `.yap`/`.yampkg`, сжатый xz.

## Что применено у нас

| Что | Было | Стало |
|---|---:|---:|
| `capsula-ui` (рендерер + панель) | 8,28 МиБ | **1,58 МиБ** |
| копия `voice-agent` в оверлее, Мини | 13,4 МиБ | **4,6 МиБ** |
| копия `voice-agent` в оверлее, 2019 | 13,3 МиБ | **5,1 МиБ** |
| пакет на диске, Мини | 14,5 МиБ | **5,3 МиБ** |
| пакет на диске, 2019 | 27,9 МиБ | **5,4 МиБ** |
| занято в `/data`, Мини | 41,0 МиБ | **8,7 МиБ** |
| занято в `/data`, 2019 | 48,2 МиБ | **11,8 МиБ** |

`capsula-ui` собирается с `-trimpath -ldflags="-s -w"` и упаковывается
`upx --best --lzma` (это маленькая программа, памяти хватает).

Для `voice-agent` lzma и `-9` на этих колонках упираются в OOM: ассистент
занимает память, а UPX на 13-мегабайтном бинарнике просит больше, чем есть.
Поэтому уровень выбирается каскадом `-9` → `-5` → `-1`, и берётся первый,
который отработал. На Мини это `-9` (4,6 МиБ), на 2019 — `-5` (5,1 МиБ).

Дополнительно удалены файлы прошлых экспериментов (копии — на RAID, в git
не попадают): на Мини три установочных бэкапа и старый `shairport-sync.prev`,
на 2019 — `ui-trial`, две резервные копии приёмника, `timing-fast` и старый
`/data/local/tmp` с первым LED-брокером.

## Почему копия `voice-agent` вообще есть

Патч громкости — 8 байт в стоковом бинарнике. Прошивка в `/rom` только для
чтения, а `/` — overlayfs с `upperdir=/data/overlay/upper`. Любая правка
файла заставляет ядро скопировать его целиком в `/data` (copy-up). Отсюда
13 МиБ; UPX сжимает уже эту копию, а на запуске ядро распаковывает её в
память. В поставку прошивочный бинарник не входит: установщик берёт его из
`/rom`, сверяет SHA-256, патчит и пакует на самой колонке.

## Страховка

`voice-agent.sh` в оверлее теперь запускает упакованную копию и, если она
умерла в первые секунды, поднимает стоковый бинарник из `/rom`. Ассистент и
watchdog всегда получают процесс; в худшем случае громкость телефона и
кнопок снова станут независимыми.

## Что сознательно не делали

- **`shairport-sync` не пересобирали с `-Os/-flto`.** Он уже 2,9 МиБ (у
  Station AirPlay — 3,8 МиБ) и собран `-O3`; экономия была бы ~0,4–0,6 МиБ,
  а риск для только что вычищенного звука выше выгоды.

## Как воспроизвести

```sh
docker run --rm -v "$PWD":/src -w /src golang:1.23-bookworm \
  sh -ec 'CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -buildvcs=false \
    -trimpath -ldflags="-s -w" -o /src/capsula-ui .'
upx --best --lzma capsula-ui
upx -t capsula-ui
```

Готовый рендерер в `packages/*/bin/capsula-ui` упакован; для чтения символов
и `go version -m` разверните его `upx -d`. Упаковка `voice-agent` выполняется
на колонке скриптом `packages/*/voice-agent-pack.sh` (см. выше про память).
